# Dogfood v0

A plan (see [how the docs are organized](../process/docs.md)): it sequences the work and states what the current build narrows; the definitions it builds are in `product/`, and where this plan and a definition disagree, the definition wins.

**Goal (2026-08-23):** get J5 Code to the state where development of J5 Code happens inside J5 Code — the second step, after the docs, toward other people being able to help. Once this milestone completes, well-defined work is farmable to any contributor.

**Definition of dogfood-ready:** crews run as J5 threads, communicate over the ledger, and reach a person in the in-app inbox whose verbatim answer closes the Exchange — with archives ending obligations loudly instead of stranding them.

## Standing guards

- **Squadron-first creation**: name the work, then attach the folder. Reusing the project-creation flow wholesale rebuilds upstream's one-to-one shape with a rename — the exact thing the Squadron definition exists to not be. The composer heading stays Squadron-named; the first-run gate stays "create your first Squadron".
- The composer's Squadron chip is in force: context-inherited, changeable until send, immutable after, and what the Registrar receives; no automatic default Squadron.
