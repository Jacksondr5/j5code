# Product glossary

The J5 product vocabulary of record. One entry per term, with a pointer to the defining document — the pointer is authoritative when detail matters. Terms inherited unchanged from T3 Code (project, thread, turn, environment, checkpoint, provider…) live in the upstream glossary at `docs/internals/glossary.md`; this file covers what J5 adds or redefines. **Writing convention:** named product concepts are written Title Case — Squadron, Crew, Captain, Manifest, Role, Playbook, Memo, Exchange — so readers know it's our concept, not the generic word; descriptive terms (fleet, agent, participant, inbox, ledger, dashboard) stay lowercase, and code identifiers are unaffected. Update this file as terms settle — a stale glossary is worse than none.

## The agent organizational family

We use a civil-nautical theme to make onboarding users to these concepts easier.

| Term         | Meaning                                                                                                                                                                                                                                                                                              |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Fleet**    | The totality — all of a user's agents across every connected server (the merged client view, X2). Never a sub-grouping.                                                                                                                                                                              |
| **Squadron** | User-created grouping of agents, artifacts, PRs, and their ledger around a large or long-running initiative. A grouping, never a boundary; single home, immutable membership; lives entirely on one server (X1). Formerly code-named "epic" (renamed 2026-08-17). Defined in `features/squadron.md`. |
| **Crew**     | The running instance of a manifest: a group of agents spawned as a unit, fixed membership, entirely within one squadron, archived only as a unit. The hands running one piece of work. (R12–R17)                                                                                                     |
| **Manifest** | The user-authored, git-versioned definition a crew is spawned from: platform-read schema (model, reasoning effort, skill allow-list, posture, playbook reference) wrapping prose role text. The user's content — portable and shareable by construction. (R12, R28)                                  |
| **Captain**  | Derived role archetype, not a platform entity: any agent with crews placed under it. Runs crews, serves as tie-breaker; never a communication router. Captaincy follows placement. (R18–R22)                                                                                                         |
| **Team**     | **Retired.** Never use; the roster concept is the crew/manifest pair.                                                                                                                                                                                                                                |

## Communication (A2A)

| Term                       | Meaning                                                                                                                                                                                                                                                                                                               |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Participant**            | Anything with its own thread: main agents, agent-created child agents, and humans. Provider-native subagents are not participants. (D1)                                                                                                                                                                               |
| **Agent**                  | An LLM participant.                                                                                                                                                                                                                                                                                                   |
| **Node**                   | A participant as rendered in the communication graph.                                                                                                                                                                                                                                                                 |
| **Exchange**               | The reply obligation: a reply-expected send mints an `exchangeId`; idempotent open per sender→receiver pair; one reply closes everything on it; the sender judges completeness at closure (R3). States: open / stalled / answered / dropped. Never called a "thread" — an exchange travels _through_ T3 threads. (D9) |
| **`regarding`**            | Optional field on exchange open linking a follow-on exchange to the one it survives. (R10)                                                                                                                                                                                                                            |
| **Communication ledger**   | The per-squadron append-only event log — source of truth for all A2A state; rows never edited, corrections are new rows; survives restarts. (A2A M1)                                                                                                                                                                  |
| **Projection**             | A derived, materialized, disposable view over the ledger (graph, inbox, stall report, playback). Wipe-and-rebuildable, never authoritative.                                                                                                                                                                           |
| **Silence notice**         | A platform-authored fact bundle appended when an agent says nothing — turn ended, no closing reply, open outbound exchanges listed structurally. Labels (awaiting-human, blocked-on-peer…) are projection policy, not ledger fact. (D6, R4)                                                                           |
| **Envelope**               | The platform's per-channel prompt wrapper teaching protocol semantics at the moment of action; carries measured time facts (R25). Versioned config the user owns.                                                                                                                                                     |
| **`trigger.fired`**        | Ledger event recording a machine trigger (schedule/check fire) as a chain's origin. Triggers are not participants. (R6)                                                                                                                                                                                               |
| **Exchange vs delegation** | Delegations to real child agents appear in the ledger; provider-native subagent work does not. (D1)                                                                                                                                                                                                                   |

## Humans and attention

| Term                                                 | Meaning                                                                                                                                                                                                                                                                                                       |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- | ------------------------------------------------------------- |
| **Person id**                                        | The durable local identity (`human:<id>`) minted at first run, used in every ledger row; external auth binds to it later. Nothing may assume exactly one human (R29's multi-human invariant). (R9)                                                                                                            |
| **Inbox**                                            | The obligation queue: open exchanges addressed to a person, urgency-ranked. Every item blocks a sender. Pure — no inferred mail, no auto-promoted stalls, no memos. (M4, R5, R26)                                                                                                                             |
| **Observability dashboard**                          | Where the human investigates "why isn't X done": stalls, blocked-on-peer chains, liveness. (R5)                                                                                                                                                                                                               |
| **Backlog pane**                                     | The pull-based view of all agents' memos. Third sibling to the inbox and observability views — shared UI allowed, shared data model never. (R26)                                                                                                                                                              |
| **Memo**                                             | A small self-addressed message an agent stores via platform tool: non-blocking, always user-visible, per-agent, agent-cleared, optionally deferred via `resurface_after` — the one platform-initiated re-injection. The v1 agent data primitive. Defined in `features/memos.md`. (R31–R35)                    |
| **Human-contact spectrum / Foreground / Background** | The lens measuring how much an agent _chats_ with the human through the chat interface (inbox Exchanges and Captain relays don't count). A Foreground agent is a touchpoint the human reads directly; a Background agent reaches the human only through the inbox or its Captain. Defined in `principles.md`. |
| **Urgency**                                          | `blocking                                                                                                                                                                                                                                                                                                     | soon | fyi` on human-addressed exchange opens; ranks the inbox. (M2) |

## Structure and work

| Term                | Meaning                                                                                                                                                                                                  |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Org placement**   | The display-tree position of an agent; equals spawner at spawn ("you command what you brief", R21 amending D10); human-only re-parent is the sole divergence. Cascade operations follow placement.       |
| **Provenance**      | Spawned-by: immutable, auto-recorded, separate from placement.                                                                                                                                           |
| **Playbook**        | User-authored step content a crew executes; the platform holds the step pointer (advanced by tool call) and injects the next step fresh. Engine = platform, steps = content. (R27; backlog candidate)    |
| **Shared squadron** | The multi-user capability: several people on one server sharing squadrons (shift handoff, two humans before one agent). Distinct from cross-device (X1–X5) and federation (X4). (R29; backlog candidate) |
| **Epic**            | Historical name for squadron in pre-2026-08-17 documents; read as squadron. Also unrelated: Traycer's own epic concept in the design workspace.                                                          |
