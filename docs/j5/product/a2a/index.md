## Grounding: the four-layer model

Established with Jackson 2026-08-16 (ELI5 versions in the session transcript; condensed here for builders):

1. **Transport** — delivery of a message into a running agent's conversation. We use T3 v2's thread layer for this (`t3_thread_send` injects into _any_ project thread; queue/steer modes; five providers). We do **not** build on v2's `delegate_task`/task layer — that is strictly parent→child (results flow to parent only, no sender identity, no reply obligation) and peer A2A lives _beside_ it, not on it. v2's topology-neutral parts we use: addressable threads + injection, the event-sourced core (command → events → projections in one transaction), and run-lifecycle events (turn started/ended).
2. **Ledger** — the per-epic append-only communication event log. Source of truth. Rows: exchange opened (with intent summary), message sent, delivery recorded, reply (closes the exchange), silence notice, participant joined/left. Never edited; corrections are new rows; survives restarts (Traycer's RAM-only open-request state is the anti-pattern).
3. **Exchanges (obligations)** — our name (D9) for Traycer's `(expectReply, responseId)` semantics, stolen whole: a reply-expected send mints an `exchangeId`; idempotent open per sender→receiver pair; follow-ups join the exchange; ONE reply carrying the id closes everything on it; taught as prompt text at the moment of action (toolsmith-validated pattern). The open exchange IS the durable fact "X owes Y an answer." Named "exchange," never "thread": a T3 thread is a whole conversation; an exchange is a reply obligation that _travels through_ T3 threads as delivery — one exchange can span several T3 threads and vice versa.
4. **Projections** — derived, materialized, disposable views over the ledger (measured-tables property: wipe and rebuild freely; never authoritative). The communication graph (nodes = participants incl. the human; **edges = exchanges, not messages**, each open/stalled/answered/dropped), the human inbox, the stall report, playback.

**Silence is measured; replies are asserted.** Typed silence notices are authored by the _platform_ about an agent when it says nothing — they are not a response schema the agent fills in (a dead agent can't fill in a schema). Detection is code over three code-level facts: delivery event + turn-end lifecycle event (hook/run-owned, never output-parsing) + absence of a reply tool-call. A `turn-ended` notice does not auto-close the exchange — it informs the waiter.
