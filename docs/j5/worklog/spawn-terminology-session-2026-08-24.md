# Spawn terminology session — rulings record (2026-08-24)

Jackson + Product lead. Origin: the "may Crew members spawn solo helpers?" question exposed that "spawn" was covering several different contracts with the human. Method: three-source inventory — the Product lead's first-hand tools (Claude Code `Agent`/`Workflow`, Traycer `create_agent`/`fork_agent`), a **live Codex agent probe** (spawned on the Codex harness and interviewed about its own tools), and a **code inventory of upstream T3's spawn surfaces** with file:line evidence (orchestrator MCP toolkit, provider-native subagent paths for Claude/Codex/Cursor/ACP, scheduled tasks). An upstream terminology check preceded naming, per Jackson: adopt over redefine.

## The comparison qualities (Jackson's)

Per surface: user sees full conversation vs summary; user can talk to it directly; single-turn vs spawner-continuable; cross-provider or same-provider; UI placement (inline block vs clickable full view).

## Findings that shaped the names

- Ten surfaces reduce to **two species**: workers inside the spawner's own provider session (same provider, session-bounded lifetime, user can sometimes watch but never converse) and full citizens (own thread, fully visible, addressable, durable, cross-provider capable).
- The Codex probe showed the worker species is not always one-shot: Codex collab children are persistent and spawner-continuable (follow-up tasks, interrupt, wait) while remaining invisible-to-user — a persistent-but-private worker.
- Upstream T3 mirrors more of provider-native workers than expected: shadow threads carry the worker's own tool calls/progress/result (Claude), and Codex-native children even hold live native thread refs (human send can resume — flagged to the Director for A-series relevance to D1's participanthood line).
- **Upstream terminology check:** "subagent" is upstream's entrenched word in code and user docs; "peer agent" appears nowhere upstream. Adopt Subagent; define Peer Agent.

## Rulings

| ID  | Ruling                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ST1 | **Subagent** = the un-addressable child species (adopting upstream's word). User cannot talk to it or move it out of the parent's tree; dies with the parent's session; same provider; almost always one-off. Visibility varies by harness; the un-addressability never does. Not a participant, never in the ledger (D1 unchanged).                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ST2 | **Peer Agent** = the citizen species (J5's term). Indistinguishable from any other agent except by provenance; full visibility, full user interaction, independent lifecycle. All platform spawning law (R21, Squadron inheritance, Registrar, ledger) governs Peer Agents only.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ST3 | **"Spawn" is the generic verb, always qualified** by what is spawned; unqualified means Peer Agent.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ST4 | **Boundary of control, documented as product law: the platform cannot control Subagent spawning and does not want to** — it happens inside the harness. J5's spawning surface is purely about Peer Agents.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ST5 | **Direction: `delegate_task` is excluded from the J5 product surface.** Jackson's analysis: it is a less capable version of the product's own goal — effectively a Peer Agent spawn plus an `expect_reply` Exchange, but wearing subagent dressing (sidebar-hidden lineage, upstream "subagent" labeling, creation requires an active parent run) — creating the awkward middle the terminology exists to eliminate. Fact-check note: the code inventory shows delegate_task children **survive the spawner** (independent durable runs; only task_cancel/interrupt stops them), contrary to the session's initial assumption — which strengthens the conclusion: it is a Peer Agent in a Subagent costume. Disposition of the inherited tool (hiding it from the J5 agent tool surface) sits with the Director. |
