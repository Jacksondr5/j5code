# Squadron creation UX session — rulings record (2026-08-24)

Jackson + Product lead; dogfood phase-3 prerequisite, front-end before back-end per Jackson. Scope: how a user creates a Squadron and creates agents under it. Designed WITHIN the law in force (E1/E2/E4/E6, R21, the creation-time Registrar as the receiving end, primitives-not-methodology) — nothing relitigated. Feature doc updated same day: `product/features/squadron.md` ("Creation UX" section, SC1–SC4). Technical design deliberately not produced — the phase-3 ticket's dev owns it within these rulings.

Jackson's framing (session input): T3's project-creation flow is folder-as-container, a 1:1 shape that is wrong for J5 — Squadrons↔folders is many-to-many.

| ID  | Ruling                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | Notes                                                                                                                                   |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| SC1 | **Targeting = resource palette, never a wall.** Squadron folder list is the default palette for agent creation in it (worktree row shows Squadron folders first, labeled; "Browse elsewhere…" below a separator reaches anything on the machine). One mechanical consequence; no permission semantics; no pre-provisioning (worktrees stay per-agent); list editable post-creation. Multi-folder = multiple folders on ONE environment; cross-machine targeting is item-5, out of scope                                    | Options rejected: pure display association (does nothing), working-set provisioning (machinery with no dogfood need, boundary-flavored) |
| SC2 | **Creation is small; first run gates on it.** Name required; description + folders optional and addable later; existing open/clone pickers reused. First-run: "create your first Squadron" before the first agent — NO auto-created Default Squadron (unnamed auto-container = junk drawer defeating the concept). Gate copy states agents need a home and name-only suffices                                                                                                                                              |                                                                                                                                         |
| SC3 | **Context, not interrogation.** Sidebar is Squadron-grouped; the composer inherits the current Squadron, visible twice — the heading ("What should we build in ⟨Squadron⟩?", the slot the folder name held in T3) and an explicit Squadron chip in the sub-bar next to the worktree row: changeable until send, immutable after (what the Registrar receives). Ruled on HTML mockups (first-run gate, creation modal, full main view with open palette dropdown), reviewed and approved by Jackson in the design workspace | Agent-spawned agents never see this surface — spawner-Squadron inheritance is R21's, already law                                        |
| SC4 | **The phase-3 minimal line.** In: create Squadron (name + folders), edit folder list, Squadron-grouped sidebar, composer chip + inheritance, palette-first worktree row. Later: clone-from-URL polish, Squadron archive UX, colors/avatars, migration of pre-Squadron projects, dashboard consequences of targeting. Never in this workstream: cross-machine targeting, boundary semantics                                                                                                                                 | Drawn so the dev-grade ticket can scope without gold-plating                                                                            |
